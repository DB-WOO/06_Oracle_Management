                               ( 저장영역 시스템 : SAN, NFS, NAS, (★ ASM), Exadata, RAW, 파일 시스템 )



1. 데이터 베이스 : 최상위 개념, 하나 이상의 테이블 스페이스 


2. 테이블 스페이스 : 하나 이상의 데이터 파일과 연결 ( 효율화를 위해 그룹화 )
                     SYSTEM : 시스템 데이터,  USERS : 사용자 데이터용

3. 세그먼트 : 논리적 객체가 할당된 공간 ( 테이블, 인덱스 )
              ( 데이터 세그먼트, 인덱스 세그먼트, 언두 세그먼트, 임시 세그먼트 .... )

4. 익스텐트 : 연속된 데이터 블록의 집합
              ( 공간이 더 필요할 때 익스텐트 단위로 공간을 할당함 )

5. 데이터 블록 : 오라클의 최소 I/O 단위, 실제 데이터 레코드가 저장되는 가장 작은 논리적 단위

● 빅파일 테이블 스페이스 : 단 하나의 거대한 데이터 파일로만 구성
    장점 : 추가 생성x       : 기존의 파일 크기만 키우면 됨
           시스템 자원 절약 : 파일 수가 적어 SGA 및 컨트롤 파일 관리가 효율적
           대용량 지원      : 테라 바이트 단위 데이터를 다루는 현재 DB환경에 적합함
    단점 : 병렬 I/O 제약    : 파일이 1개  →  일반 파일 시스템에서는 I/O가 특정 디스크에 몰릴 수 있음 
           복구 시간        : 워낙 크기 떄문에 손상 시 복구시간 오래걸림
  
스몰파일 테이블 스페이스 : 여러 데이터 파일을 가질 수 있음 ( DB 관리 단순화 )

구분        Smallfile Tablespace (기본값)   Bigfile Tablespace
파일 개수   최대 1,022개까지 추가 가능       오직 1개
최대 크기   파일당 약 32GB (8K 블록 기준)    파일당 약 32TB (8K 블록 기준)
주요 용도   일반적인 환경, 다중 디스크 분산	대규모 데이터 웨어하우스(DW), VLDB
스토리지    일반 파일 시스템	                ASM(Automatic Storage Management) 권장

● SYSTEM 테이블스페이스

  - 데이터 딕셔너리, 시스템 롤, 프로시저, 함수, 트리거 저장
  - 데이터베이스 구동을 위해 반드시 Online 상태
  - 사용자 데이터를 여기다 저장하는 것은 절대 금지 (성능, 관리 ...)
  - SYS 스키마 소유의 객체들의 위치

● SYSAUX 테이블스페이스

  - SYSTEM 테이블스페이스의 보조 역할 ( 시스템 부하 줄이는 용도 )
  - AWR, 통계정보, EM 관련 데이터베이스의 부가 구성요소 저장 ( SYSTEM에 넣었던 것을 분리하게 되었음 )
  - 꽉 차도 DB 구동에는 문제 없으나 통계정보, 갱신... 들이 작동 안할 수 있음

● ASM ( Automatic Storage Management ) : 리눅스 자동 디스크 관리 오라클 프로그램

  - 컴퓨터를 안끄고 하드 디스크 추가 가능
  - 디스크를 추가하자마자 데이터를 분산 시킴 ( 스트라이핑 )
  - 데이터를 다른 디스크로 미러링  →  백업 자동
