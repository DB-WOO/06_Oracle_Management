DB 저장영역

- Redo Log File     : 변경사항을 기록하는 파일
- Data File         : Data를 저장하는 파일
- Password File     : 인스턴스의 구성 정보가 들어있는 파일
- Conrol File       : DB 구조정보를 담고있는 파일
- Backup File       : 백업본
- Alert Log File    : 오라클을 진단하기 위한 파일
- Trace File        : 오라클을 진단하기 위한 파일
- Archive Log File  : 리두 로그 파일의 백업본

--------------------------------------------------------------------------------------------------------------------------

● 1. Redo Log File

  - 전원 OFFㆍ인스턴스 비정상 종료  →  메모리(Buffer Cache)에는 있지만, DataFile에 저장 되지 않은 영역을 Redo하여 복구 
 
  - Fast Commit : 트랜잭션 커밋  →  데이터 파일에 즉시 기록 X, Redo Log에 먼저 기록하여 성능 최적화

  - 리두 로그 순환 : ALTER DATABASE LOG SWITCH;  →  다음 그룹으로 넘어가서 기록 시작 ( 현재 그룹이 가득 찰 경우에도 넘어감 )

  - Multiplexing : 하나의 파일이 손상되어도 다른 멤버로 운영 가능

  - LGWR 프로세스가 현재(Current)에 로그 기록
      CURRENT  : 현재 LGWR이 기록 중인 그룹
      ACTIVE   : 기록은 끝, 기록 변경 사항이 Datafile에 저장되지 않아 인스턴스 복구 시 필요한 상태
      INACTIVE : DataFile에 저장 완료, 인스턴스 복수 할때 필요하지 않은 상태  →  재사용 가능

  - 로그 스위치 발생 시, DBWR → 데이터파일 기록 하도록 트리거

  

SQL> select group#, status, archived, sequence#, members from v$log;
    GROUP# STATUS           ARC  SEQUENCE#    MEMBERS
---------- ---------------- --- ---------- ----------
         1 CURRENT          NO          19          1
         2 INACTIVE         YES         17          1
         3 INACTIVE         YES         18          1


SQL> alter system switch logfile;
SQL> select group#, status, archived, sequence#, members from v$log;

    GROUP# STATUS           ARC  SEQUENCE#    MEMBERS
---------- ---------------- --- ---------- ----------
         1 ACTIVE           YES         19          1
         2 CURRENT          NO          20          1
         3 INACTIVE         YES         18          1

-- 계속 로그 스위치 하면 현 그룹을 ACTIVE로 바꾸고 다음 그룹이 CURRENT로 바뀜 
   →  계속 넘어가다가 다음 그룹이 ACTIVE 상태면 Redo Log File에 작성하고 넘어가는 듯
-- alter system checkpoint; 실행 시 current 제외하고 전부 INACTIVE 상태가 됨


-- 추가
alter database add

  SYSAUX : SYSTEM 보조, AWR 저장

● 3. Parameter File

  ① PFILE (Parameter File)         : 텍스트 파일,   직접 편집가능 (수동 관리),         init[ORACLE_SID].ora
  ② SPFILE (Server Parameter File) : 바이너리 파일, 직접 수정불가 (오라클 서버가 관리), spfile[ORACLE_ISD].ora,  SCOPE=SPFILE/BOTH

  - show parameter [Parameter_Name] 적으면 나오는 값들
    + show parameter spfile  →  값 O : SPFILE 사용 중,  NULL : PFILE 사용 중일 가능성 큼

  - 파라미터 파일 찾는 우선순위
    spfile[ORACLE_SID].ora  →  spfile.ora  →  init[ORACLE_SID].ora

  - SCOPE
    ALTER SYSTEM SET [Parameter_Name] = 500 SCOPE=(MEMORY / SPFILE / BOTH);
      MEMORY : 휘발성, 재기동하면 사라짐      -- MEMORY 옵션이 안먹히는 파라미터도 있음 → SPFILE 옵션 적용
      SPFILE : 파일에 저장, 다음 기동시 적용
      BOTH   : 가능한 바로 적용, 영구 저장

  - spfile 없을 경우
    create spfile form pfile;

  - spfile, pfile 둘다 있는 경우  →  찾는 우선순위에 따라 spfile로 기동하려고 함
    startup pfile = '$ORACLE_HOME/dbs/initorcl.ora'  -- pfile 기동 방법


  - spfile을 무리하게 설정

    alter system set db_files=1000000 scope=spfile;  -- 최대 65534 (2^16 - 2), 1000000은 너무 커서 startup 할때 읽지도 안하고 에러
    파라미터 파일 경로로 찾아감
    [ ]$ cat [ORACLE_HOME]/dbs/init[ORACLE_SID].ora | grep db_files
    *.db_files=100  # 65534 보다 작게 수정

    [ ]$ sqlplus / as sysdba

    create spfile from pfile;  -- 직접 수정한 pfile로 spfile회복

    startup 가능


  - pfile 없음, spfile 손상
      backup을 만들어 둔 경우, cp로 backup

● 4. Password File

  - DB Shutdown 상태에서도 SYSDBA, SYSOPER 권한을 가진 사용자가 원격 접속 할 수 있도록 인증 정보 저장

  - 일반 사용자 인증 USER$ 테이블 (DB:OPEN)  →  Shutdown 시 읽기 불가  →  DB 외부에서 인증 처리
  [ ]$ sqlplus [SYSDBA ID]/[SYSDBA PW]U@[DB 서버 아이피]:[포트번호]/[서비스 명] as sysdba

  - 리눅스에서의 보통 위치 : $ORACLE_HOME/dbs/orapw<ORACLE_SID>

  - 패스워드 파일에 등록된 유저

      grant sysdba to scott;    
      select username, sysdba from v$pwfile_users;
      USERNAME   SYSDB
      ---------- -----
      SYS        TRUE
      SCOTT      TRUE   -- 리스너 접속 가능
    
      show parameter remote_login_passwordfile
      NAME                                 TYPE        VALUE
      ------------------------------------ ----------- -----------
      remote_login_passwordfile            string      EXCLUSIVE


      alter system set remote_login_passwordfile=none      scope=spfile;  -- VALUE가 NONE으로 바뀌며 리스너 접속 불가능해짐
      alter system set remote_login_passwordfile=exclusive scope=spfile;




  - 패스워드 파일 삭제 시 복구 방법
      [ ]$ orapwd file=orapw[ORACLE_SID] password=oracle_4U entries=5 format=12   -- orapw 뒤에 [ORACLE_SID]를 떼어내서 SID로 인식함

● 5. Control File

  - DB의 구조정보, 상태, 위치정보 등을 가지고 있는 파일

  - DB Shutdonw 시 startup 할때 읽히는 파일
    ① close → nomount : parameter file   -- nomount에서 인스턴스 구성
    ② nomount → mount : control file
    ③ mount → open    : datafile, redo log file...


  - RMAN 백업
    [ ]$ rman target /
    RMAN> configure controlfile autobackup on;
    RMAN> backup database;

  - Control File 백업 
    alter database backup controlfile to trace as '[HOME]/cre_controlfile.txt';

      컨트롤 파일이 모두 깨졌을 때 똑같이 다시 만들기 위한 백업
      바이너리 파일인 컨트롤 파일을 우리가 읽고 편집할 수 있는 메모장(.txt) 형태로 저장함

  
  - 멀티플렉싱 : 컨트롤 파일을 여러개 쓰는 것    (추가ㆍ위치 또는 이름 수정ㆍ삭제 시 에도 다 방법 같음)

  - Rman Backup 저장 위치, 공간 사용률 확인
    SELECT NAME
         , ROUND(SPACE_LIMIT / 1024 / 1024) AS "Total_MB"
         , ROUND(SPACE_USED / 1024 / 1024) AS "Used_MB"
         , ROUND(SPACE_RECLAIMABLE / 1024 / 1024) AS "Reclaimable_MB"
         , ROUND((SPACE_USED - SPACE_RECLAIMABLE) / SPACE_LIMIT * 100, 2) AS "Used_Pct"
      FROM V$RECOVERY_FILE_DEST;
